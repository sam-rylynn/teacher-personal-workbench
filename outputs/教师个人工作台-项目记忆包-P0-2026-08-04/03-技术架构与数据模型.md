# 技术架构与数据模型

## 当前结构

```text
教师个人工作台
├── React / Vinext 界面
│   ├── 今日
│   ├── 学生档案
│   ├── 教学课表
│   ├── 事项中心
│   └── 教学资料
├── 设备本地工作区
│   ├── 用户配置
│   ├── 学生与测评
│   ├── 课次
│   ├── 事项
│   └── 资料索引
└── 手机只读内容
    ├── 工作区修订号
    ├── 重点学生摘要
    ├── 待上课课次
    └── 未完成事项
```

当前没有应用后端数据库。`db/schema.ts` 为空；`.openai/hosting.json` 中 D1 与 R2 都是 `null`。Cloudflare/Vinext 文件只是构建与站点脚手架，不能作为云数据能力或公开部署的证据。

## 运行时

- Node.js：`>=22.13.0`。
- 应用：Next 16.2.6、React 19.2.6、Vinext 0.0.50、Vite 8.0.13。
- 样式：单一 `app/globals.css`，含响应式断点。
- 构建目标：Vinext + Cloudflare Vite 插件。
- 当前开发脚本使用类 Unix 环境变量写法，Windows 原生命令行兼容尚未完成。
- `app/chatgpt-auth.ts` 是未接入主页面的认证辅助文件，不能作为已完成登录或账号系统的证据。

## 数据根对象

`WorkbenchDataV1`：

```text
schemaVersion
storageKind
meta
user
students[]
lessons[]
tasks[]
resources[]
mobileSnapshot
```

### 学生

`StudentRecord` 包含：

- 内部 ID、姓名、班级、头像缩写和颜色。
- `assessments[]`：每次测评独立记录。
- `recentIssue`：当前近期问题，可为空。
- `homeSchool`：当前家校协同状态。

### 测评

`AssessmentRecord` 包含：

- 测评名称、学科、日期。
- 满分、成绩、班级排名、参考人数、班级均分。
- 核对状态：已核对或待核对。
- 来源：手工录入、表格导入或图片识别。
- 可选核对时间。

成绩和排名变化由 `getAssessmentChange()` 比较相邻的已核对测评计算，不再推算虚构历史排名。

### 近期问题

`StudentIssue` 包含标题、具体情况、发现日期、状态、下一步和可选复核日期。状态为待处理、观察中或已缓解。

### 家校协同

`HomeSchoolProfile` 包含：

- 沟通难度 1—5。
- 沟通说明。
- 辅助意愿 1—5。
- 辅助说明。
- 更新时间。

这些值必须由老师选择，不能由 AI 自动固化。

### 课次

`LessonSession` 包含标题、学科、班级、起止时间、地点、备课清单、状态和课前提醒分钟数。

当前模型是具体课次，不是完整的循环课表模板；学期循环、调课和例外规则尚未建模。

### 事项

`WorkbenchTask` 包含类别、标题、截止时间、预计分钟数、状态、提醒时间、关联对象和可选完成时间。

类别为教学、学生、行政或论文；状态为待开始、进行中或已完成。

### 资料

`WorkbenchResource` 当前只保存资料索引：标题、类别、学科、年级或班级、位置和更新时间。P0 不读取附件内容，也没有文件上传或创建流程。

## 核心计算

- `getAssessmentChange()`：最新和上一次已核对测评、分数变化、标准化得分率变化、排名变化。
- `rankPriorityStudents()`：根据近期问题、成绩/排名下降和家校状态生成当前关注顺序。
- `summarizeTaskDuration()`：事项总时长、未完成时长、已完成时长和分类时长。
- `summarizeWorkbench()`：学生、问题、家校、事项、课次和平均成绩汇总。

学生关注排序是工作台内部辅助排序，不应向老师表述为对学生能力或家庭的自动评价。

## 写权限边界

写入上下文分为：

```text
desktop + workspace        → 允许
mobile + mobile-snapshot  → 拒绝
任何 mobile-snapshot      → 拒绝
```

`applyWorkbenchUpdate()` 在修改前检查权限，并对工作区深拷贝；`saveDeviceLocalWorkbench()` 在实际存储前再次检查权限。手机路径不会获得保存、创建、更新或删除能力。

## 手机内容

`createMobileReadOnlySnapshot()` 当前生成固定摘要：

- 最多 5 名重点学生。
- 最多 5 个待上课课次。
- 最多 8 件未完成事项。
- 生成时间、来源修订号和工作台汇总。

当前 P0 没有“老师逐项选择手机内容”的真实配置界面。手机内容是代码固定的最小摘要，不要把它描述成已经支持任意范围选择。

电脑端后续修改不会改变已生成的手机内容；只有再次执行“更新手机看板”才会生成新内容。

## 本地存取与迁移

- 当前键：`teacher-workbench:device-local:v1`。
- 当前 schema：1。
- 旧键：`teacher-workbench:device-local:v0`、`teacher-workbench:data`。
- 读取失败时会载入新的虚构种子并给出提示。
- 早期扁平学生成绩和事项可转换为当前结构。

尚缺：原子文件保存、自动备份、用户可见恢复、数据导出、加密、跨浏览器迁移和冲突处理。

## 当前日期逻辑债

P0 的虚构数据固定在 2026-09-16/17，根组件和手机更新汇总也仍以 `2026-09-16` 计算当日课次。正式初始化前必须改成老师设备的本地日期、时区和当前学期配置，不能把演示日期带入客户数据。
