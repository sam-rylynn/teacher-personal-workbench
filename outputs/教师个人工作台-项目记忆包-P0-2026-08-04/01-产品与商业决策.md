# 产品与商业决策

本文只记录用户已经明确确认的方向。实现情况另见 `02-P0当前实现状态.md`，不要把产品决策误写成已经完成的功能。

## 一句话定位

向老师个人销售并一次性交付的本地优先工作台，把学生状态、课表、事项和资料串成老师每天可执行的工作闭环。

它不是“老师版钉钉 + 教务 ERP + AI 工具箱”，重点是让老师知道下一步该处理什么。

## 首批用户

- 小学、初中、高中学科老师。
- 班主任。
- 教培老师。
- 单个老师典型数据规模不超过约 80—100 名学生。

## 标准销售品

`标准工作台 + 一次初始化配置`

销售流程设想：

1. 用户下单。
2. 远程把标准工作台部署到用户使用的 Agent 环境。
3. 为用户建立其本人控制的私有 GitHub 仓库，并上传代码。
4. 完成一次初始化配置与验收。
5. 用户获得永久个人使用和修改权。

授权边界：允许本人永久使用和修改；禁止转售和传播。正式销售前仍需形成可签署的授权文本。

## 服务边界

- 售价包含标准框架和第一次初始化，不包含持续维护。
- 首装只配置字段、模板、提醒、导入映射、工作台名称、个性化名称、配色或形象等轻量内容。
- 不接受修改核心逻辑、大规模功能开发或长期内容运营作为首装服务。
- 后续微调、数据更新和内容迭代由用户使用自己的 Agent 完成。

## 设备边界

- Windows 与 macOS 都要支持，但当前 P0 还没有完成双系统安装和启动验收。
- 电脑端负责完整记录和修改。
- 手机端只查询、搜索和查看电脑端最近一次更新的内容。
- 最终确认不允许手机实时修改电脑工作区。

## 数据与隐私边界

- 产品方不代替老师选择要交给 Agent 或 AI 的资料范围。
- 售前页面只使用虚构演示数据。
- 正式客户数据由老师在自己的设备上管理；产品方不以持续托管数据为商业模式。
- 老师连接自己的 AI，产品方不提供统一 AI 账号或长期代管密钥。
- 本地优先只能减少产品方的数据持有，不能自动消除学生和家长个人信息相关责任。
- 发送给外部 AI 的内容仍需遵循最小必要、透明、访问控制、删除和安全边界。

## 提醒边界

- 目标是本地提醒和导出到系统日历。
- 不做微信、短信或云推送。
- 当前 P0 只保存课前提醒和事项提醒字段，尚未真正触发系统提醒或导出日历。

## AI 边界

- AI 嵌入具体工作流，不单独做一个庞大的 AI 中心。
- AI 只能生成可编辑、可追溯、需老师确认的建议或草稿。
- 不自动主观评分，不自动形成固定负面标签，不未经老师确认向家长发送内容。
- 当前 P0 尚未接入真实 AI；老师日常界面也已隐藏开发者术语。

## 核心内容优先级

功能板块已经足够，不再扩展一级模块。继续深化以下内容：

1. 学生档案：成绩、排名、进退步、近期问题、家校协同。
2. 课表：真实课次、时间、地点、提醒和对应详情。
3. 事项：行政、教学、学生和论文任务统一管理。
4. 资料：查找和复用现有资料。
5. 手机查看：只展示最近一次更新的摘要内容。

已经明确淘汰的学生表达包括“学习证据”“事实时间线”等对老师日常记录价值较低的内容。

## 交互与语言原则

- 所有人数、成绩、排名、升降和耗时必须从真实记录计算，不能写死。
- 家长沟通难度与辅助意愿由老师手动选择，并可更新。
- 这些等级只描述当前协同过程，不是家庭的永久标签。
- 老师界面不出现 `Agent、写入、快照、仓库、密钥、令牌、配对、档案编号` 等后台术语。
- 所有可见控件必须闭环；没有真实结果的入口先隐藏。
