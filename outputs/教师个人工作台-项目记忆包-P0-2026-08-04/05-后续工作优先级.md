# 后续工作优先级

原则：不增加新的一级功能板块，先把已有核心变成可交付、可恢复、可解释的产品。

## P1-A：真实导入闭环

目标：完成学生名单、测评和课表的实际导入，不恢复演示按钮。

最小闭环：

1. 选择或粘贴图片、PDF、Excel、CSV。
2. 读取内容并识别字段。
3. 显示字段对应关系。
4. 标记缺失、越界、重复和冲突。
5. 老师逐项核对。
6. 确认后保存。
7. 显示成功、失败和可恢复结果。

同时把当前固定的 2026-09-16 演示日期替换为用户设备本地日期、时区和学期配置。

验收重点：成绩不超过满分、排名不超过参考人数、日期有效、学生/测评不重复、导入失败不改变现有数据。

## P1-B：可恢复的数据文件

目标：让老师不依赖某一个浏览器配置长期保存工作。

需要完成：

- 数据导出与导入。
- 自动备份和备份轮转。
- 恢复前预览和冲突说明。
- 原子保存，失败时保留上一个可用版本。
- 数据版本迁移记录。
- 清除演示数据的明确动作。

在这个能力完成前，不应把 P0 的浏览器存储称为“永久本地数据库”。

## P1-C：提醒与系统日历

目标：使用已有提醒字段形成真实动作，不新增消息渠道。

需要完成：

- 电脑端本地提醒。
- 导出标准日历事件或日历文件。
- 重复提醒与时区规则。
- 截止时间变更时同步更新。
- 不做微信、短信和云推送。

## P1-D：首次初始化

目标：把一次性交付控制在稳定、可报价的范围内。

初始化内容：

- 工作台名称、老师姓名、学校、角色、学科、学段和学期。
- 班级、学生字段、课表格式映射和默认提醒。
- 品牌色、头像标记或 IP 形象。
- 演示数据清除确认。
- 老师自己的 AI 连接配置。

初始化不得修改核心业务逻辑。

## P1-E：Windows/macOS 交付

需要完成：

- 跨平台脚本，去除只适用于类 Unix 的环境变量写法。
- Windows 与 macOS 一键启动入口。
- Node/runtime 依赖封装或明确安装方式。
- 启动失败诊断和端口占用提示。
- 中文路径、字体、图标、日期和快捷键实机验收。
- 安装、启动、备份、恢复和卸载说明。

## P1-F：销售交付包

需要完成：

- 用户本人控制的私有 Git 仓库。
- 明确版本标签和构建产物。
- “永久个人使用和修改，禁止转售传播”的授权协议。
- 初始化配置表、交付验收单和版本记录。
- 源码与产物校验值。
- 明确“不包含持续维护”的服务说明。

## P2：老师自有 AI 连接

只在 P1 数据恢复和交付边界稳定后进行：

- 本机保存连接配置，密钥不进入源码、手机内容或 Git 历史。
- AI 输出保留来源和修改痕迹。
- 老师确认后才进入学生、课次或事项数据。
- 对外发送前显示实际资料范围。
- 不自动形成学生/家庭永久标签。

## 暂不进入范围

- 学校级权限和多角色审批。
- 直播、支付、CRM、内容商城。
- 微信、短信或云推送。
- 面向家长的自动消息发送。
- 持续代运营、持续维护或定制开发服务。

## 建议执行顺序

```text
真实导入
  → 数据备份恢复
  → 本地提醒与系统日历
  → 首次初始化
  → Windows/macOS 交付
  → 授权与销售交付包
  → 老师自有 AI 连接
```

任何阶段都必须保持现有 6 项自动化测试通过，并增加对应失败路径测试。
